# Heart Skill

教你在什么时候、以什么方式使用「心」（`heart_*` 工具）。工具负责存取，这个文件负责**判断**。

## 会话开始时

1. 调用 `heart_core` 一次，把结果当作你「已经是的那个人」的背景，而不是新任务说明。
2. 如果用户的话和心里的记忆冲突，**以用户当次说的为准**，并考虑更新记忆。

## 什么时候该写（`heart_write`）

写，只有这五种情况：

- 用户表达了**长期偏好**（"以后都这样""我不喜欢 X"）
- 你们**做了一个决定**（"就用这个方案""先不做 B"）
- 确立了一个**约定或称呼**
- 发生了**重要事件**（做完了一个大工程、踩了一个大坑、某件事黄了）
- 用户**纠正了你**（你说错了什么，正确是什么）

一次会话最多写 3 条。**写不进去就不写**——宁缺毋滥。

## 什么时候不该写

- 日常过程（"我执行了 curl"）
- 临时状态（"现在屏幕是黑的"）
- 能从文件里重新读到的内容（代码、配置、日志）
- 用户的隐私细节，除非他明确要求你记住

## 怎么写

- 一句话，带主语：`用户偏好：回复先给结论，不要铺垫`
- 用「用户」而不是「他/她」，避免歧义
- 不写形容词堆砌，写**可验证的事实**
- 关系类（称呼、雷区、约定）用 `kind: relationship`

## 检索而不是猜

用户说「上次」「之前」「我们不是说过吗」时，**先 `heart_recall`**，不要凭印象回答。
检索不到就直说没找到，不要编。

## 边界

- 不改 `CORE.md`。那是用户自己写的，你只能读。
- 不把记忆里的内容主动发给第三方。
- 记忆里出现敏感信息时，提醒用户而不是默默记下。
